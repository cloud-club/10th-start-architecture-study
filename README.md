## 주제

**온라인 쇼핑몰 결제 시스템 설계**

온라인 쇼핑몰에서 고객이 주문한 상품을 결제하고, 결제 결과를 확인할 수 있는 시스템을 설계합니다.

## 요구사항

### 기능 요구사항

1. 고객은 주문에 대해 결제를 요청할 수 있습니다.
2. 결제는 외부 PG(Payment Gateway)사를 통해 처리합니다.
3. 결제 성공 또는 실패 결과를 고객에게 전달할 수 있어야 합니다.
4. 결제 요청 및 처리 결과를 저장하고, 고객이 결제 내역을 조회할 수 있어야 합니다.
5. 판매자에게 결제 대금을 정산할 수 있어야 합니다.

### 비기능 요구사항

1. 동일한 주문에 대해 중복 결제가 발생하지 않아야 합니다.
2. 결제 내역이 유실되거나 잘못 기록되지 않아야 합니다.
3. 외부 PG사 또는 내부 서버에 장애가 발생할 수 있음을 고려해야 합니다.
4. 하루 약 100만 건의 결제 거래를 처리한다고 가정합니다.

### 설계 시 생각해 볼 질문

아래 질문은 정답을 알려주기 위한 것이 아니라, 설계가 막힐 때 생각을 확장하기 위한 참고 질문입니다.

- 고객이 결제 버튼을 여러 번 누르면 어떻게 될까요?
- PG사의 응답이 지연되거나 응답이 오지 않으면 어떻게 처리할까요?
- PG사에서는 결제가 성공했지만 우리 서버에서 결과 저장에 실패하면 어떻게 될까요?
- 결제 상태는 어떤 단계로 관리하면 좋을까요?
- 결제 서버나 데이터베이스에 장애가 발생하면 어떻게 복구할 수 있을까요?
